# Internacionalização

<a id="supported-languages"></a>

A configuração fica em `.codexspec/config.yml`. Os modelos continuam em inglês;
os agentes escrevem as interações e os artefatos gerados nos idiomas configurados.
Os 13 códigos de idioma padrão são `en`, `zh-CN`, `zh-TW`, `ja`, `ko`, `es`,
`fr`, `de`, `pt`, `ru`, `it`, `ar` e `hi`.
O código da CLI para português é `pt`; a documentação localizada e os catálogos
de tradução usam `pt-BR`.

<a id="language-dimensions"></a>

## Dimensões de idioma

| Dimensão | Chave de configuração | Na inicialização | Definir depois | Controla |
|-----------|------------|-------------------|-----------|----------|
| Saída/base | `language.output` | `--lang` | `config --set-lang` | Idioma usado quando as demais dimensões não têm configuração própria |
| Interação | `language.interaction` | `--interaction-lang` | `config --set-interaction-lang` | Conversas e saída da CLI |
| Documento | `language.document` | `--document-lang` | `config --set-document-lang` | Requisitos, especificações, projetos técnicos, planos e tarefas |
| Commit | `language.commit` | `--commit-lang` | `config --set-commit-lang` | Mensagens de commit e textos gerados nos fluxos de trabalho com Git |

Quando uma dimensão não tem um idioma próprio configurado, ela usa
`language.output`, independentemente das outras dimensões. Se esse valor também
não estiver definido, usa `en`. `language.templates` continua sendo `en`.

```bash
codexspec init my-project --ai both \
  --interaction-lang zh-CN --document-lang en --commit-lang en

codexspec config
codexspec config --set-document-lang en
codexspec config --list-langs
```

Na primeira inicialização com TTY, o idioma base é solicitado, a menos que você
informe `--lang` ou as três opções específicas de idioma. `--force` confirma
automaticamente as outras solicitações de inicialização, mas não elimina essa
escolha de idioma. Sem TTY, o padrão é inglês. Ao inicializar novamente, as chaves
de idioma que você não definir explicitamente são preservadas.

## Documentação traduzida

O site e os README da raiz são mantidos em oito idiomas. As configurações de idioma em tempo de execução controlam a saída do agente; elas não traduzem automaticamente a documentação do repositório. As páginas em inglês de `docs/en/` são a fonte das traduções. O inglês é publicado na raiz do site, e as demais versões ficam nos respectivos caminhos de idioma.

[English](https://zts0hg.github.io/codexspec/) · [中文](https://zts0hg.github.io/codexspec/zh/) · [日本語](https://zts0hg.github.io/codexspec/ja/) · [한국어](https://zts0hg.github.io/codexspec/ko/) · [Español](https://zts0hg.github.io/codexspec/es/) · [Français](https://zts0hg.github.io/codexspec/fr/) · [Deutsch](https://zts0hg.github.io/codexspec/de/) · [Português](https://zts0hg.github.io/codexspec/pt-BR/)

## Manutenção das traduções

Use as entradas de tradução e revisão semântica exclusivas do repositório em qualquer um dos assistentes. Elas são ferramentas de manutenção, não comandos públicos instalados por `codexspec init`. As regras compartilhadas estão em `internal/references/doc-translation.md`, e a terminologia, em `docs/i18n/glossary.yml`.

```text
$codexspec:translate-docs --source docs/en/getting-started/installation.md --lang all
$codexspec:check-i18n-semantics --source docs/en/getting-started/installation.md --lang all --strict

/codexspec:translate-docs --source docs/en/getting-started/installation.md --lang all
/codexspec:check-i18n-semantics --source docs/en/getting-started/installation.md --lang all --strict
```

Selecione as páginas em inglês alteradas, leia toda a fonte e preserve cada condição, valor padrão, exclusão, exemplo e token técnico. Escreva documentação técnica natural no idioma de destino; não é necessário preservar a estrutura das frases em inglês. Avalie a fidelidade e a naturalidade separadamente e confira os links para títulos traduzidos nas páginas de destino.

O inventário registra os pares exatos de origem e destino e os hashes das fontes. As verificações mecânicas detectam diferenças de estrutura, exemplos de código, tokens e links, mas não comprovam equivalência semântica. Revise todos os idiomas selecionados e corrija omissões ou expressões pouco naturais antes de aceitar a tradução. Uma simulação apenas mostra a seleção.

## Verificação do build e dos diagramas

A CI da documentação faz o build com validação estrita do MkDocs. A tradução e a revisão semântica continuam sendo tarefas explícitas de manutenção; um build bem-sucedido, por si só, não comprova a qualidade da tradução. Confira na prévia as páginas afetadas, a navegação entre idiomas, os layouts em telas estreitas e os dois temas.

```bash
uv sync --extra dev --extra docs
uv run python -B -m internal.doc_translation inventory --lang all
uv run python -B -m internal.doc_translation verify --lang all
uv run mkdocs build --strict
uv run mkdocs serve
```

O site reutiliza os PNGs de fluxo de trabalho do README em `assets/workflow/` por meio de `hooks/workflow_assets.py`; não mantém outro conjunto de imagens-fonte nos diretórios de documentação. Os links de imagem específicos de cada tema acompanham o seletor claro/escuro do site. Atualize a fonte do diagrama, os catálogos, o layout e todos os recursos gerados seguindo o manual de manutenção compartilhado.
