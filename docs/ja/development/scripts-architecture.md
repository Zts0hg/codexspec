# スクリプトとインストールの構成

## ランタイムとコマンドのソース

`src/codexspec/` の Python CLI は、`templates/commands/` の完全なコマンドテンプレート、ドキュメントテンプレート、共通のレビュー基準をインストールします。Claude Code にはスラッシュコマンド、Codex には同じソースから生成したネイティブスキルを提供します。28 の公開コマンドは、どちらのホストでも同じワークフローの規則に従います。

## インストールとプロジェクトコンテキスト

`codexspec init` はプラットフォーム用のヘルパーと指定されたアシスタント連携を選択します。共通リソースは `.codexspec/`、Claude コマンドは `.claude/commands/codexspec/`、Codex スキルは `.agents/skills/` に配置されます。インストールされた CLI は、ワークフローで使うワークスペースのルーティングや、保護チェック付きのヘルパー操作も担います。

初期化では既存の `AGENTS.md` と `CLAUDE.md` の CodexSpec 管理ブロックを更新し、その外側にあるプロジェクト独自の内容を保持します。`--force` はインストール済み成果物を更新し、更新時の確認に応答しますが、コンテキストファイル全体の置き換えや無関係な設定の削除は行いません。CLI のインストールだけではプロジェクトは初期化されません。

## プラットフォーム別ヘルパー

Unix では `scripts/bash/` の Bash スクリプト、Windows では `scripts/powershell/` の PowerShell スクリプトを使います。機能の作成と前提条件チェックは対象機能を解決し、機械可読のコンテキストを返します。`common.sh` と `common.ps1` は各プラットフォームの共通処理を提供し、`review-context` はレビュー対象の情報収集を支援します。独立したコミット用ランタイムは、両プラットフォームで `src/codexspec/commit_runtime.py` から `.codexspec/scripts/commit-staged-helper.py` にコピーされます。

## 機能の識別と成果物の互換性

機能名は `YYYY-MMDD-HHMMss-name` 形式で、分単位のタイムスタンプ、小文字の英数字 2 文字の接尾辞、ASCII の名前で構成されます。完全な機能名がワークスペースを識別するため、その明示的なパスまたはブランチを使って続行します。連番の `NNN-name` 識別子はサポートしていません。過去の機能との互換性は成果物に適用されます。`requirements.md` や `design.md` がない場合、元の確認を捏造せず、追跡可能性の制限を明示します。

## コントリビューター向けの保守

正本となるソースを編集し、派生コピーを再生成して配布内容を検証します。フラグメント方式を採用するコマンドは `internal/command_templates/sources/` で編集し、完全な `templates/commands/` ファイルを生成します。それ以外のコマンドテンプレートは直接編集します。インストール済みの Claude／Codex コピーを手作業で変更しないでください。

パッケージには公開テンプレートと 2 つのプラットフォーム別スクリプトディレクトリが含まれます。`internal/` の保守ツール、`docs/` のサイトソース、テスト、ワークフロー図のソースと画像は含まれません。スクリプトの収録範囲を `scripts/` 全体に広げないでください。

## 拡張機能の作成資料

リポジトリには、拡張機能のマニフェストテンプレート、コマンド例、[拡張機能開発ガイド](https://github.com/Zts0hg/codexspec/blob/main/extensions/EXTENSION-DEVELOPMENT-GUIDE.md)が含まれます。
これらは拡張機能を作成するための資料です。現在の CLI に拡張機能のインストール・一覧・削除コマンドはなく、
`extension.yml` のコマンドやフックを自動で読み込むこともありません。
共通レビューリソースには、`.codexspec/review-code/` 配下にプロジェクト独自の内容を追加できます。
初期化時には、置換を求めない限り、既存リソースへの編集内容や追加ファイルを保持します。
