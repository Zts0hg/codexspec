# 国際化

<a id="supported-languages"></a>

設定は `.codexspec/config.yml` に保存します。テンプレートは英語のままですが、
エージェントは設定された言語で対話文と成果物を作成します。
標準の言語コードは 13 個です：`en`、`zh-CN`、`zh-TW`、`ja`、`ko`、`es`、`fr`、`de`、`pt`、`ru`、`it`、`ar`、`hi`。
ポルトガル語の CLI コードは `pt` で、ローカライズされたドキュメントと翻訳カタログでは `pt-BR` を使います。

<a id="language-dimensions"></a>

## 言語の個別設定

| 区分 | 設定キー | 初期化時 | 後から設定 | 対象 |
|-----------|------------|-------------------|-----------|----------|
| 出力・基本言語 | `language.output` | `--lang` | `config --set-lang` | 他の言語設定で指定がない場合の基本言語 |
| 対話 | `language.interaction` | `--interaction-lang` | `config --set-interaction-lang` | 会話と CLI 出力 |
| ドキュメント | `language.document` | `--document-lang` | `config --set-document-lang` | 要件、仕様書、設計、計画、タスク |
| コミット | `language.commit` | `--commit-lang` | `config --set-commit-lang` | コミットメッセージと Git ワークフローで生成する文章 |

各言語設定は、それぞれ独立して `language.output`、次に `en` の順でフォールバックします。
`language.templates` は `en` のままです。

```bash
codexspec init my-project --ai both \
  --interaction-lang zh-CN --document-lang en --commit-lang en

codexspec config
codexspec config --set-document-lang en
codexspec config --list-langs
```

初回の TTY 初期化では、`--lang` または 3 つすべての個別言語オプションを指定していなければ、基本言語の選択を求めます。
`--force` は他の初期化時の確認を自動で承認しますが、この言語選択は省略しません。
非 TTY での初期化では、デフォルトで英語を使います。再初期化時も、明示的に設定していない言語キーは保持されます。

## 多言語ドキュメント

サイトとルートの README は 8 言語で保守しています。実行時の言語設定はエージェントの出力を制御するもので、リポジトリのドキュメントを自動翻訳するものではありません。`docs/en/` の英語ページを翻訳元とし、英語はサイトのルート、他の言語はそれぞれのロケールのパスで公開します。

[English](https://zts0hg.github.io/codexspec/) · [中文](https://zts0hg.github.io/codexspec/zh/) · [日本語](https://zts0hg.github.io/codexspec/ja/) · [한국어](https://zts0hg.github.io/codexspec/ko/) · [Español](https://zts0hg.github.io/codexspec/es/) · [Français](https://zts0hg.github.io/codexspec/fr/) · [Deutsch](https://zts0hg.github.io/codexspec/de/) · [Português](https://zts0hg.github.io/codexspec/pt-BR/)

## 翻訳の保守

どちらのアシスタントでも、リポジトリ専用の翻訳・意味レビュー用エントリを使えます。これらは保守用ツールで、`codexspec init` がインストールする公開コマンドではありません。共通規則は `internal/references/doc-translation.md`、用語集は `docs/i18n/glossary.yml` にあります。

```text
$codexspec:translate-docs --source docs/en/getting-started/installation.md --lang all
$codexspec:check-i18n-semantics --source docs/en/getting-started/installation.md --lang all --strict

/codexspec:translate-docs --source docs/en/getting-started/installation.md --lang all
/codexspec:check-i18n-semantics --source docs/en/getting-started/installation.md --lang all --strict
```

変更した英語ページを選び、原文全体を読んで、条件、既定値、対象外の範囲、例、技術的なトークンをすべて保持します。訳文は対象言語の技術文書として自然に書き、英語の文構造に合わせる必要はありません。意味の忠実性と表現の自然さを別々に確認し、見出しへのリンクは実際のリンク先ページに照らして検証します。

インベントリには正確な原文と訳文の組み合わせ、および原文のハッシュが記録されます。機械的な検査は構造、コード例、トークン、リンクの差を検出できますが、意味の一致までは証明できません。選択したすべての言語をレビューし、欠落や不自然な表現を修正してから受け入れます。ドライランは選択範囲のプレビューのみです。

## ビルドと図の確認

ドキュメントの CI は MkDocs の厳格な検証でビルドします。翻訳と意味レビューは別途明示的に実施する保守作業であり、ビルド成功だけでは翻訳品質を保証できません。変更したページ、言語ナビゲーション、狭い画面での表示、両テーマをプレビューしてください。

```bash
uv sync --extra dev --extra docs
uv run python -B -m internal.doc_translation inventory --lang all
uv run python -B -m internal.doc_translation verify --lang all
uv run mkdocs build --strict
uv run mkdocs serve
```

サイトは `hooks/workflow_assets.py` を通じて `assets/workflow/` の README 用ワークフロー PNG を再利用し、ドキュメントディレクトリに別の原画像を保持しません。テーマ別の画像リンクはサイトの明暗切り替えに従います。図を更新する際は共通の保守手順書に従い、元図、翻訳カタログ、レイアウト、生成済みリソースをすべて更新します。
