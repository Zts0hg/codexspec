# Internacionalización

<a id="supported-languages"></a>

La configuración se guarda en `.codexspec/config.yml`. Las plantillas permanecen
en inglés; el agente redacta las conversaciones y los artefactos generados en
los idiomas configurados. Los 13 códigos de idioma estándar son `en`, `zh-CN`,
`zh-TW`, `ja`, `ko`, `es`, `fr`, `de`, `pt`, `ru`, `it`, `ar` y `hi`.
Para portugués, la CLI utiliza `pt`; la documentación localizada y los catálogos
de traducción utilizan `pt-BR`.

<a id="language-dimensions"></a>

## Idiomas de interacción, documentos y commits

| Dimensión | Clave de configuración | Al inicializar | Cambiar después | Qué controla |
|-----------|------------|-------------------|-----------|----------|
| Salida/base | `language.output` | `--lang` | `config --set-lang` | Idioma de respaldo para las demás dimensiones |
| Interacción | `language.interaction` | `--interaction-lang` | `config --set-interaction-lang` | Conversación y salida de la CLI |
| Documentos | `language.document` | `--document-lang` | `config --set-document-lang` | Requisitos, especificaciones, diseños, planes y tareas |
| Commits | `language.commit` | `--commit-lang` | `config --set-commit-lang` | Mensajes de commit y textos generados en los flujos de trabajo con Git |

Si no se define el idioma de una dimensión, se utiliza `language.output` y,
en su defecto, `en`. Esta regla se aplica de forma independiente a cada
dimensión. `language.templates` permanece en `en`.

```bash
codexspec init my-project --ai both \
  --interaction-lang zh-CN --document-lang en --commit-lang en

codexspec config
codexspec config --set-document-lang en
codexspec config --list-langs
```

En la primera inicialización desde una terminal TTY se pide el idioma base,
a menos que indiques `--lang` o las tres opciones de idioma específicas.
`--force` confirma automáticamente las demás solicitudes de inicialización,
pero no omite esta selección. Sin TTY, se utiliza el inglés de forma
predeterminada. Al volver a inicializar, se conservan las claves de idioma
que no hayas establecido explícitamente.

## Documentación traducida

El sitio y los README de la raíz se mantienen en ocho idiomas. La configuración de idioma en tiempo de ejecución controla la salida del agente; no traduce automáticamente la documentación del repositorio. Las páginas en inglés de `docs/en/` son la fuente de traducción. El inglés se publica en la raíz del sitio y las demás versiones, bajo sus rutas de idioma.

[English](https://zts0hg.github.io/codexspec/) · [中文](https://zts0hg.github.io/codexspec/zh/) · [日本語](https://zts0hg.github.io/codexspec/ja/) · [한국어](https://zts0hg.github.io/codexspec/ko/) · [Español](https://zts0hg.github.io/codexspec/es/) · [Français](https://zts0hg.github.io/codexspec/fr/) · [Deutsch](https://zts0hg.github.io/codexspec/de/) · [Português](https://zts0hg.github.io/codexspec/pt-BR/)

## Mantenimiento de traducciones

Usa las entradas de traducción y revisión semántica exclusivas del repositorio desde cualquiera de los dos asistentes. Son herramientas de mantenimiento, no comandos públicos instalados por `codexspec init`. Las reglas compartidas están en `internal/references/doc-translation.md` y la terminología, en `docs/i18n/glossary.yml`.

```text
$codexspec:translate-docs --source docs/en/getting-started/installation.md --lang all
$codexspec:check-i18n-semantics --source docs/en/getting-started/installation.md --lang all --strict

/codexspec:translate-docs --source docs/en/getting-started/installation.md --lang all
/codexspec:check-i18n-semantics --source docs/en/getting-started/installation.md --lang all --strict
```

Selecciona las páginas en inglés que hayan cambiado, lee la fuente completa y conserva todas las condiciones, valores predeterminados, exclusiones, ejemplos y tokens técnicos. Redacta documentación técnica natural en el idioma de destino; no es necesario conservar la estructura de las frases en inglés. Revisa por separado la fidelidad y la naturalidad, y comprueba los enlaces a encabezados traducidos contra sus páginas de destino.

El inventario registra los pares exactos de origen y destino y los hashes de las fuentes. Las comprobaciones mecánicas detectan diferencias de estructura, ejemplos de código, tokens y enlaces, pero no demuestran equivalencia semántica. Revisa todos los idiomas seleccionados y corrige omisiones o expresiones poco naturales antes de aceptar la traducción. Una ejecución en seco solo muestra la selección.

## Comprobaciones de compilación y diagramas

La CI de documentación compila con la validación estricta de MkDocs. La traducción y la revisión semántica siguen siendo tareas de mantenimiento explícitas; compilar correctamente no demuestra por sí solo la calidad de la traducción. Previsualiza las páginas afectadas, la navegación entre idiomas, los diseños para pantallas estrechas y ambos temas.

```bash
uv sync --extra dev --extra docs
uv run python -B -m internal.doc_translation inventory --lang all
uv run python -B -m internal.doc_translation verify --lang all
uv run mkdocs build --strict
uv run mkdocs serve
```

El sitio reutiliza los PNG de flujo de trabajo del README en `assets/workflow/` mediante `hooks/workflow_assets.py`; no mantiene un segundo conjunto de imágenes fuente en los directorios de documentación. Los enlaces de imágenes por tema siguen el selector claro/oscuro del sitio. Actualiza la fuente del diagrama, los catálogos, el diseño y todos los recursos generados según el manual de mantenimiento compartido.
