## Context

Implement the design's deterministic Python substrate first, then connect the two distributed
agent templates and the public CLI. The repository already provides a Python 3.11 Typer package,
pytest/ruff, dynamic CLI translations, template installers for Claude and Codex, and established
self-bootstrap regeneration. The feature adds no runtime dependency and no new packaging root.

The most failure-sensitive work is the shared state boundary: exact JSON validation, canonical
blueprint parsing, atomic file/Git persistence, linked-worktree discovery, and concurrent run/Git
ownership. Those foundations must be tested in isolation and synthetic repositories before command
templates depend on them.

## Goals and Non-Goals

**Goals:**

- Implement design C1-C12 with complete REQ/NFR traceability.
- Keep pure document/protocol code separate from subprocess/filesystem adapters.
- Prove concurrency, interruption recovery, Git environment isolation, and merge-history behavior
  through deterministic tests.
- Ship `blueprint` and `auto-dev` to both supported agent integrations and
  `codexspec show-blueprint` through the installed Python CLI.
- Update command counts, translations, documentation, and derived artifacts in lockstep.

**Non-Goals:**

- A new delivery-branch/cherry-pick command or automatic PR/MR publisher.
- New blueprint statuses or automatic dependency/priority scheduling.
- A Python-embedded Claude/Codex runner; agent interpretation remains template-driven.
- Rebase or reconstruction of the fixed automatic-development branch.

## Tech Stack and Repository Constraints

- **Runtime**: Python 3.11+, Typer, Rich for diagnostics only, standard-library JSON/dataclasses,
  subprocess, tempfile, hashlib, and POSIX/Windows file-lock primitives.
- **Agent commands**: English source Markdown in `templates/commands/`, dynamically translated at
  execution; derived Claude/Codex forms regenerated by `codexspec init`.
- **Testing**: pytest with temporary Git repositories, fake clocks, failure injection, subprocess
  concurrency, CLI runner tests, and template contract tests; ruff for Python quality.
- **Source boundaries**: Modify `templates/commands/` and `src/codexspec/`; do not hand-edit derived
  `.claude/commands/` or `.agents/skills/` files.
- **Distribution lockstep**: Two new core templates require installer metadata, total/core counts,
  both count-test sites, all eight README rows, documentation, and regenerated derived forms.
- **Git isolation**: Every Git subprocess aimed at a resolved/temporary repository must clear all
  repository-local environment variables reported by Git, including caller index/worktree/object
  overrides.

## Plan-Level Decisions

### Decision 1: Build pure protocol and document modules before repository adapters

**Context**: Parser and schema defects can be tested exhaustively without Git, while mixing them
with subprocess behavior makes failure classification harder to diagnose.

**Options Considered**:

1. Implement one end-to-end helper module first.
2. Implement pure value objects, parser, serializer, and request/response validation first, then
   inject repository persistence.

**Decision**: Option 2. Keep pure blueprint/protocol code in a focused Python module and provide
repository state through explicit adapters.

**Rationale**: Enables complete malformed/relationship-invalid fixture matrices and keeps the four
domain results independent from transport failures.

**Covers**: REQ-004, REQ-005, REQ-006, REQ-008, REQ-009, REQ-010, NFR-002; Design: C2, C3,
Decision 2

**Decision Level**: Plan-level implementation sequencing; no product or architecture change.

### Decision 2: Use test-controlled clocks and fault points for coordination tests

**Context**: Run ownership reclamation and blueprint transaction recovery cannot be tested reliably
with wall-clock sleeps or uncontrolled process termination.

**Options Considered**:

1. End-to-end sleeps and real crashes only.
2. Inject a clock and named transaction fault points for unit/integration tests, supplemented by a
   small real subprocess concurrency test.

**Decision**: Option 2.

**Rationale**: Deterministic tests can cover every boundary quickly; real subprocess tests still
verify OS lock behavior.

**Covers**: REQ-011, REQ-018, REQ-019, NFR-001; Design: C4, C7, C8, Decisions 3 and 4

**Decision Level**: Plan-level test strategy.

### Decision 3: Keep Typer handlers thin and machine output decoration-free

**Context**: `show-blueprint` must provide raw stdout and hidden helper actions must emit exact JSON.

**Options Considered**:

1. Put repository and protocol logic directly in `src/codexspec/__init__.py` handlers.
2. Keep handlers as argument/stdin/stdout adapters over reusable modules.

**Decision**: Option 2. Use `sys.stdout.buffer` for raw blueprint success output and JSON encoding
without Rich; use translated stderr diagnostics only on failures.

**Rationale**: Prevents presentation behavior from corrupting shell/agent machine contracts and
keeps the existing CLI entrypoint maintainable.

**Covers**: REQ-006, REQ-010, REQ-023, REQ-024, NFR-004; Design: C5, C11, Decision 7

**Decision Level**: Plan-level implementation choice.

### Decision 4: Implement Git behavior through one sanitized runner and fixture builder

**Context**: Worktree setup, fetch, ancestry, merge, commit, and tests all target repositories other
than the maintainer checkout and are vulnerable to inherited Git environment state.

**Options Considered**:

1. Call subprocess independently at each site.
2. Route all production and test-fixture Git commands through one runner that sets `cwd`, clears
   local Git environment variables, captures evidence, and raises typed errors.

**Decision**: Option 2.

**Rationale**: Prevents foreign-repository operations from mutating the caller's index/config and
gives all coordination components consistent error evidence.

**Covers**: REQ-019, REQ-020, REQ-021, REQ-022, NFR-001; Design: C1, C8, Git isolation

**Decision Level**: Plan-level implementation choice based on verified repository pitfall.

### Decision 5: Regenerate derived integrations only after source templates and metadata pass

**Context**: `init --force --ai both` is the legitimate self-bootstrap mechanism, but running it
repeatedly during template edits creates noisy review state.

**Options Considered**:

1. Regenerate after every template change.
2. Finish source templates, metadata, and contract tests first; regenerate once, then run drift and
   full-suite verification.

**Decision**: Option 2.

**Rationale**: Preserves source-of-truth discipline while minimizing derived churn and still keeps
the feature branch self-consistent before final review.

**Covers**: REQ-001, REQ-014; Design: C10, C12, Decision 8

**Decision Level**: Plan-level build ordering.

## Risks and Trade-offs

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Activity ownership is reclaimed while an old agent tool call is still running | Low | High | Fencing tokens, ownership assertion immediately before every mutation, fake-clock boundary tests, and old-owner rejection after takeover |
| Blueprint file is replaced but commit is interrupted | Medium | High | Recovery record plus failure injection at each C4 transaction boundary |
| A path-limited commit disturbs unrelated staged content | Medium | High | Synthetic repo tests with pre-staged and unstaged unrelated files before every blueprint/feature commit variant |
| Merge conflict blocks a concurrent blueprint commit | Medium | Medium | Shared Git-write/merge ownership, fixed lock order, and multiprocess wait/release tests |
| Worktree discovery accepts a lookalike path | Low | High | Validate Git porcelain registration, canonical path, branch ref, and common directory together |
| Global auto-next still fires inside auto-dev | Medium | High | Uniform delegation clause in every chain template plus source/derived contract tests |
| Command metadata/docs counts drift | Medium | Medium | Apply the repository's distributed-command lockstep checklist and whole-repo count grep |
| Windows lock or replacement semantics differ | Medium | High | Isolated lock abstraction, Windows-compatible implementation, platform CI tests, no POSIX-only shell dependency |

## Verification Strategy

### Pure protocol tests

- Positive fixture for every request/result variant and status transition.
- Negative fixture for every missing, extra, null, type-invalid, conditionally invalid, stale, and
  forbidden relationship.
- Parser fixtures for LF/CRLF, separators, embedded ID mismatch, duplicate IDs, malformed prefixes,
  invalid statuses/directories, and canonical round trips.

### Repository and concurrency tests

- Synthetic local-only, remote-tracking, descendant, and diverged histories.
- Hostile inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, and object-directory environment
  while proving the maintainer index remains unchanged.
- Multiprocess incompatible blueprint writes, Git/blueprint lock ordering, second auto-dev rejection,
  stale-owner takeover, old-token fencing, and unexpected transaction recovery.
- Merge, fast-forward, squash, rebase, and cherry-pick integration graphs with exact file-diff and
  commit-list assertions.

### CLI and template tests

- Byte-for-byte stdout, empty stdout on errors, translated stderr, and no filesystem/Git mutation
  for every `show-blueprint` prerequisite failure.
- Hidden helper stdin/stdout schema and non-zero transport failure behavior.
- Contract tests assert command responsibilities, all exact operation names/fields, stage order,
  global-auto-next suppression under delegation, and unchanged direct stage behavior.

### Full verification

- Focused pytest files while implementing each phase.
- `uv run ruff check src/ tests/`.
- `uv run pytest` after source and derived forms are synchronized.
- `git diff --check` and distribution/count/documentation sweeps.
