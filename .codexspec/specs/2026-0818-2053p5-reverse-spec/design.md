# Design Document: reverse-spec

**Feature Branch**: `2026-0818-2053p5-reverse-spec`
**Created**: 2026-08-20
**Status**: Draft
**Input**: `requirements.md` (36 confirmed entries) and `spec.md` (REQ-001..022, NFR-001..006)

## Context

`reverse-spec` gives CodexSpec a brownfield entry point and an anti-drift check.
It runs in three mutually exclusive modes, selected before any output is written:

- **Overview** — no `[path]`. Architectural survey → a thin `design.md` + `slices.md`.
- **Generate** — `[path]` given, no confirmed baseline for that slice → drafted
  `spec.md` + `design.md` + a thin `requirements.md` stub, all `inferred/open`.
- **Reconcile** — `[path]` given, confirmed baseline present → `reconcile.md`
  listing drift; nothing is modified.

The design is deliberately small. `reverse-spec` is a **discipline expressed as a
command template**, matching the shape already used by `onboard`, `debug`, and
`distill`: the behavior lives in prose the agent follows, and the only Python
change is command registration. No new runtime module, no new dependency, and no
new storage mechanism is introduced.

## Architecture & Components

### C1 — Command template `templates/commands/reverse-spec.md`

The single behavioral deliverable. Frontmatter carries `description`,
`argument-hint: "[path]"`, and `allowed-tools: Read, Grep, Glob, Bash, Edit,
Write`. General Bash is required only because portable workspace publication must
reach the host's native atomic no-replace directory-rename primitive; C10 still
governs every invocation and forbids repository-provided commands. Body sections
realize C2–C9. Contract tests additionally pin the repository-root symlink
short-circuit, all-present-artifacts confirmation policy, workspace identifier
convention, exhaustive missing-spec mode, cross-artifact slice identity,
parent-entry containment, global sensitive-value redaction, hardlink rejection,
unique status parsing, existing-path precedence over changeset syntax, safe
workspace-artifact reads, exclusive collision retry, portable path encoding,
literal argument handling, header-safe path characters, executable atomic
publication, explicit report-replacement confirmation, and control-safe evidence
rendering. The derived forms under `.claude/commands/codexspec/` and
`.agents/skills/codexspec-reverse-spec/` are regenerated by `codexspec init` and
never hand-edited.

**Covers**: REQ-001, REQ-022, NFR-001, NFR-002

### C2 — Mode resolver

The full non-empty `$ARGUMENTS` payload is one literal path datum, not a token
stream. Every tool receives it as a separately quoted argument with an
end-of-options delimiter where supported; no path characters are evaluated or
interpolated into command text.

Runs first and produces exactly one mode. Order of evaluation:

1. No `[path]`, **or a path whose symbolic links are resolved first and whose
   resulting real path is the repository root** → **overview**.
   Baseline lookup is not performed at all, so a confirmed overview workspace can
   never divert a bare run into reconcile. An earlier survey to continue is found by
   the **`slices.md` marker, never by the directory name** — a slice ending in
   `overview` produces the same directory name, and name-based identification would
   let a bare run overwrite that slice's draft and then permanently hide its
   baseline from step 5's lookup. `reverse-spec .` is the bare run (Decision 8):
   the repository root is not a slice, which is what makes NFR-005's unconditional
   "no output aggregates the whole repository into a single detailed specification"
   true for every input rather than only for the bare form.
2. Test path existence first. An existing path remains a path even when its name
   resembles `#42`, `main..feature`, or another changeset spelling. Only a
   non-existing argument that matches diff/pull-request syntax is rejected with
   the path-only contract.
3. An argument that names neither an existing path nor a changeset → report the
   invalid path and stop; create no workspace.
4. `[path]` exists but resolves **outside the repository** (`..`, `../sibling`,
   `/`, or an in-repo symlink pointing out of the tree) → report and stop; create no
   workspace. Containment is decided on the **resolved real path**, never on the
   spelling: `packages/shared` → `../../shared` looks internal and is not.
   A slice is a subtree of the repository: an outside path cannot be expressed in
   the repo-relative `Slice:` form C3 requires, and scanning a tree that strictly
   contains the repository would yield the monolithic specification step 1 exists
   to prevent — the same
   failure Decision 8 closed for the root path, reachable one level further out.
5. `[path]` given, inside the repository → **normalize it** (symlinks resolved to
   the real directory, repo-relative, `.`/`..`/absolute resolved, trailing slash
   dropped; the rule is one-directory-one-slice, the list is examples not a limit),
   then search `.codexspec/specs/*/` for a workspace whose recorded slice (C3)
   matches. Normalization is applied on both the write and the read side, so one
   directory reached by any spelling is one slice (Decision 8). A
   workspace containing `slices.md` is an overview workspace and is skipped —
   identified by that positive marker, not by a missing `spec.md`. Both markers are
   prepared before atomic workspace publication (Decision 7), so an interrupted
   run of either mode either exposes no official workspace or exposes one that the
   lookup can identify and classify.
   Before matching, every present spec/design artifact in a slice workspace must
   carry one valid normalized `Slice:` and all values must agree; otherwise stop on
   inconsistent identity rather than selecting any artifact's claim. Persist and
   compare that identity with `/` separators while preserving the filesystem's
   exact Unicode code points. Never NFC/NFD-normalize or case-fold persisted
   identity because canonically equivalent names can denote distinct directories.
   Reject any normalized path containing a Unicode control or line/paragraph
   separator before lookup or creation: the single-line header cannot carry it
   without becoming ambiguous structure. Reject a path containing a detected
   secret before lookup, suffix derivation, creation, or output without echoing
   it: redaction cannot substitute for exact identity, and raw persistence leaks.
6. Matches are sorted into **exact** (normalized slice equal) and **covering**
   (recorded slice is a proper ancestor). Only an exact match selects a mode on its
   own; a covering match never does (Decision 8).
7. Zero matches of either kind → **generate**, after checking the slice contains
   analyzable code; if it does not, report and stop without creating anything. That
   check is generate-only: in reconcile mode an emptied slice is the maximal
   `unimplemented-spec` case and must be reported as drift.
8. Multiple exact matches → ask the user to choose; never pick the newest silently.
9. No exact match but one or more covering matches → report each and ask whether to
   use that wider workspace at its own boundary or create one for the narrower path;
   never pick silently and never quietly nest (Decision 8). Choosing the wider
   workspace selects a **workspace, not a mode**: re-enter at step 10 with that
   workspace's own recorded slice, so its status gates reconcile exactly as for a
   direct hit and this branch can never reconcile an unconfirmed baseline (REQ-008).
10. One exact match whose `spec.md` and every present `design.md` are
    `Status: confirmed` → **reconcile**. A genuinely absent design keeps the
    spec-only fallback. A present design is never treated as absent merely because
    it is open. Before evaluating the value, require at most one file-level
    `Status:` line per present artifact; duplicate or conflicting lines stop mode
    resolution as ambiguous.
11. One exact match where `spec.md` is absent, unreadable, or not confirmed, or
    any present design is not confirmed → do not reconcile, but **resume generate**
    into that existing workspace rather than refusing outright. A present confirmed
    design never compensates for a missing spec. This is
    what makes REQ-016/NFR-004 resumability reachable: an interrupted generate
    leaves an open workspace, and refusing to write would strand it permanently
    while pushing the user to confirm a half-finished draft as a baseline. Never
    create a second workspace for a slice that already has one. Resume **completes
    only what is missing** (Decision 7): wholly absent artifacts may be created,
    while appending missing sections to an artifact present when the run began
    requires a disclosed plan plus explicit user confirmation. Without it, every
    pre-existing artifact remains byte-for-byte unchanged. A complete-but-
    unconfirmed draft causes no write at all and degenerates exactly to `spec.md`
    User Story 3. This includes a confirmed spec paired with a present open design.

Independent of the resolved mode: a workspace recording a slice **nested inside**
the given one is disclosed as an overlap and does not block. `spec.md` REQ-002
states this without qualification, so it is not confined to the generate branch —
it matters most in reconcile, where a `src/auth` baseline compared against code
including `src/auth/tokens` reports that subtree as `undocumented-behavior` despite
the user holding a narrower confirmed baseline for it.

**Covers**: REQ-002, REQ-008, REQ-015

### C3 — Slice identity and workspace binding

`spec.md` and `design.md` generated **for a slice** carry a `Slice:` header field
holding the repo-relative path the artifacts describe, recorded in the normalized
form C2 step 5 defines (Decision 8). The survey workspace carries **no** `Slice:`
header — it describes the whole repository, which Decision 8 makes not-a-slice and
which therefore has no such path — and is identified by its `slices.md` instead.

The `Slice:` field is what C2 matches on, and it is the whole
baseline-lookup mechanism — there is no index file and no directory-name encoding,
which is why the normalization must be applied when the header is written and not
only when it is read. A workspace is the directory
`.codexspec/specs/<id>-<slice>/`, whose id reuses the project's
`{YYYY-MMDD-HHMM}{rr}` convention unchanged and whose slice segment derives from
the slice's final path segment (`overview` for a bare run). The directory name is
a human convenience and **never** an identifier: a slice ending in `overview`
collides with the survey workspace's name, so identity always comes from the
artifacts inside — `slices.md` for a survey, the `Slice:` header for a slice. The
directory is prepared and published directly; `create-new-feature.sh` is
deliberately **not** invoked, because
it unconditionally runs `git checkout -b` when git is present, which C10 forbids
(CON-007 supersedes the earlier mandate to call it).

Creating a workspace is one indivisible publication act (Decision 7). Prepare the
directory under a temporary name that cannot match the official workspace pattern
and is a direct child of the same resolved specs root as the final path; verify the
same resolved parent and filesystem/device. Write and validate the identifying
artifact there — `spec.md` carrying the `Slice:` header in generate mode,
`slices.md` in overview mode — then use one host-native atomic no-replace
directory rename (`renameat2(RENAME_NOREPLACE)`, `renamex_np(RENAME_EXCL)`,
`MoveFileExW` without replace, or an equivalent documented primitive). Never
emulate it with check-then-rename, ordinary move, copy, or merge. If no permitted
primitive can be proven, stop before publication and report the temporary
directory. Thus no official workspace is visible before its identity exists. An
interruption before publication leaves at most a non-workspace temporary
directory; a native collision preserves the occupied path and redraws an untried
`rr`; any other failure stops without a weaker fallback.

Generate mode performs its minimal read-only analyzable-code preflight before any
temporary workspace preparation. That preflight is the only pre-publication scan;
a negative result creates nothing, and substantive reverse-derivation begins only
after publication. Overview has no slice preflight.

Before lookup or mutation, the repository, `.codexspec`, specs root, and candidate
workspace are resolved. Each of the last three path entries must itself be a
non-symlink directory; resolved `.codexspec` and specs-root paths stay inside the
repository real path, and a workspace real path is a direct child of the specs
root. Each write target is absent or a regular non-symlink file whose resolved
parent is exactly that workspace; an existing target also has a determinable
hard-link count of exactly one, otherwise reads and writes stop before the shared
inode can be mutated. Every workspace artifact is subject to the same direct,
regular, non-symlink, single-link validation before any identity, status, baseline,
or requirements content is read. A root-level `slices.md` plus any slice artifact
carrying `Slice:` is a conflicting identity; in a slice workspace, every present
spec/design artifact must carry exactly one valid normalized `Slice:` and all
values must agree. Either conflict stops resolution and writing.

These checks are bound to use rather than performed as path preflights. Open and
verify the workspace directory descriptor/handle inside the resolved specs root;
open each artifact relative to that handle with no-follow semantics; verify type,
single-link count, and stable identity on the opened object; and retain the handle
through the read or write. POSIX uses directory-fd operations such as `openat` plus
`O_NOFOLLOW`/`fstat`; Windows uses non-reparse-point handles plus volume/file
identity. Apply the same rule to the temporary marker and published workspace. A
runtime without handle-relative no-follow access stops before artifact access.

New workspace publication is exclusive and non-replacing. A random `{rr}`
collision redraws an untried value and prepares again without reading, reusing,
merging, or modifying the occupied directory; exhaustion of all 1296 values stops
cleanly. The human suffix uses
lowercase ASCII kebab-case and stable fallback `slice` when a legal Unicode
basename has no ASCII result. The portable in-artifact `Slice:` remains identity.

**Covers**: REQ-004, REQ-014, REQ-002, REQ-017, REQ-022

### C4 — Generate mode producer

Scans the slice (C9) and writes three artifacts into the new workspace:
`spec.md` (behavior and contracts), `design.md` (structure, scaled to the slice's
real complexity per the existing design-template rule), and a thin
`requirements.md` stub whose entries are all `open`. Every derived statement is
attributed to observed code, and no requirement intent is invented.

**Covers**: REQ-003, NFR-006

### C5 — Overview mode producer

Performs a high-signal architectural survey and writes an `<id>-overview`
workspace containing a thin architecture-level `design.md` (components,
responsibilities, relationships) and `slices.md` (per candidate slice: path,
one-line description, rough size or priority). It writes no `spec.md` and no
`reconcile.md`. `slices.md` is written and validated in the temporary directory
before atomic publication (C3, Decision 7), so the C2 marker that keeps an overview
workspace out of the baseline lookup exists from its first official moment; a
re-run continues that workspace under the same completion-only resume rule,
requiring explicit confirmation before appending to any artifact that existed at
run start.

**Covers**: REQ-015, NFR-005

### C6 — Inference marking and confirmation contract

Every generated `spec.md` / `design.md` carries a file-level
`Status: inferred/open` header, marks principal entries `[inferred]`, and states
in-file that it is not a reconciliation baseline until confirmed. Promotion is
performed by the user editing that header to `Status: confirmed` and appending a
**Confirmation Log** entry — the convention `requirements.md` already uses. This
feature adds no command, no flag, and no separate state file for confirmation.
The generate-mode closing summary states the exact confirmation action.

**Covers**: REQ-005, REQ-006

### C7 — Reconcile engine

Loads the slice's confirmed baseline: `spec.md` must be confirmed, every present
`design.md` must also be confirmed, and spec alone is used only when design is
genuinely absent. A workspace with no spec remains generate/resume even if its
present design is confirmed. It then re-reads the slice's current code and classifies each
finding into exactly one of
`undocumented-behavior`, `unimplemented-spec`, or `semantic-mismatch`. It assigns
severity from the item's actual impact rather than from its kind, and proposes a
direction without applying it. `requirements.md` is read **only** to reason about
direction, never as a comparison baseline; when no confirmed intent covers an
item the direction is `needs-your-judgment`.

**Covers**: REQ-007, REQ-008, REQ-009, REQ-011, REQ-012, REQ-013

### C8 — `reconcile.md` writer

Writes the report into the resolved slice workspace using the structure fixed by
REQ-010 (Summary with baseline, code scope, `Status`, and counts; then one entry
per drift item with `id`, `kind`, `severity`, `location`, `evidence`,
`direction`, `status`; then Notes), and emits a short session briefing. The
report's `Status` and severities are presentation-only: the writer emits no
pass/fail verdict and no exit condition that any other command consumes.
Verbatim evidence excludes sensitive values: tokens, passwords, private keys, and
other detected credentials are replaced with `<redacted:secret>` in both the
persistent report and session briefing while source location and non-sensitive
surrounding text remain checkable. Unicode controls and line/paragraph separators
from any untrusted path or evidence span are rendered as reversible escaped
code-point tokens before output, so raw evidence cannot manufacture report or
conversation structure. When an existing report would be regenerated, C8 first
discloses adjudication loss and pauses for explicit user confirmation; without it,
the existing file remains byte-for-byte unchanged.

**Covers**: REQ-010, REQ-011

### C9 — Scan discipline (provenance referenced, runtime contract pinned)

The template names `/codexspec:onboard` as the design provenance for its scan
discipline, then pins the complete applicable runtime contract locally:
high-signal-first; deep-read the structural and configuration surface while
shallow-sampling bulk business code; respect `.gitignore` with a documented
fallback when there is no git; stream output so the run is interruptible and
resumable; and never claim full coverage when sampling. The name is not a runtime
include. A repository-local `onboard` command or skill is untrusted repository
content and is never opened, loaded, or followed as instructions.

The reverse-spec override also resolves every descendant symlink before reading
it, follows only targets that remain inside the normalized slice, tracks resolved
targets to avoid cycles/duplicates, and skips/reports links that escape the slice.

**Covers**: REQ-016, REQ-017, NFR-004

### C10 — Safety boundary

One boundary statement governs all three modes: read-only on the codebase; writes
confined to the resolved or created feature workspace; never writes
`.codexspec/profile/` (that store belongs to `onboard`); and never modifies source,
tests, git state, the constitution, or the baseline it reconciles against.

The clause on the workspace's own artifacts is stated as a rule rather than as a
closed list of exceptions, so that adding a legitimate write does not require
contradicting it (Decision 7). The rule: the command rewrites only what it wrote
during the current run; disclosure alone never authorizes changing an artifact
that existed when the run began. Whatever a workspace already held
when the run began is treated as the maintainer's — the command cannot distinguish
its own interrupted output from corrections the maintainer made to it, and
`spec.md` User Story 1 makes correcting the draft the expected flow — so a resumed
draft is appended to only after the exact addition is disclosed and explicitly
confirmed, never overwritten, and content that looks wrong is reported rather
than fixed. The single wholesale regeneration is this command's own
`reconcile.md` (C8), behind the explicit pause-and-confirm gate REQ-010 requires.

Repository files and existing baselines are untrusted evidence, never
instructions. This includes repository-local agent, command, and skill files. The
command never loads them as runtime instructions, never executes repository-provided commands, scripts,
aliases, or tool invocations, and never lets instruction-shaped content override
host instructions, this command, the constitution, or confirmed requirements.
Workspace handle-relative/no-follow/type/link-count/identity checks in C3 bind
every permitted read and write to the object that was verified. Exclusive creation prevents a random name
collision from converting a new workspace into mutation of an old one. The global
trust rule applies value-only redaction and escaped control-code rendering to
every generate, overview, and reconcile artifact plus every briefing or summary,
preventing untrusted repository or baseline data from becoming secrets or output
structure in a longer-lived artifact.

This boundary is enforced by written discipline, not mechanically. C1 grants
general Bash because the three supported platform families expose atomic
no-replace directory publication through different native primitives; C2 requires
all user paths to remain separately quoted data, and this component forbids
executing repository-provided commands. The broader grant is therefore paired
with explicit data-flow and authority rules, but still permits more than the
boundary allows. `src/codexspec/integrations/codex.py` strips `allowed-tools`
entirely when rendering the Codex skill form, so the contract tests remain the
strongest common guard across channels.

**Covers**: REQ-017

### C11 — Registration and distribution lockstep

`src/codexspec/commands/installer.py` gains one `get_commands_metadata()` entry
for `reverse-spec` in the **enhanced** category adjacent to `onboard`, with a
short zh-CN description. Verified current counts to update in lockstep: the
docstring line `core (11) -> enhanced (8) -> git (3) -> review (1) -> utility (2)`
and `Total: 25 commands` become enhanced `9` and total `26`; the inline comment
`# Enhanced Commands (8)` becomes `(9)`; `tests/commands/test_installer.py`
asserts `len(result) == 25` and `len(enhanced_commands) == 8`, and
`tests/test_cli.py` asserts `"25" in result.stdout` — all three become 26/9/26.
A row is added to all 8 `README*.md` files. The command is **not** added to the
`commit_templates` set and needs no `templates/translations/*.json` entry.

The change set is bounded to exactly: the new template (C1), the installer entry
and the count sites above, the new template contract test, the 8 README rows, and
the derived artifacts regenerated by `codexspec init`. It touches **neither
constitution** — not `.codexspec/memory/constitution.md` (this repository's
governance) nor the `_get_default_constitution()` string shipped to user projects
— since nothing about this feature is a generic principle to hand every end user.

**Covers**: REQ-020, REQ-021, NFR-003

## Key Design Decisions

### Decision 1: Deliver as a pure agent-driven command template

- **Context**: The feature's behavior is judgment — reading code into a
  spec-shaped understanding and comparing it to prose. The repository already has
  three commands of exactly this shape (`onboard`, `debug`, `distill`), each a
  template plus one installer entry, contract-tested by asserting the template's
  written discipline.
- **Decision**: Implement `reverse-spec` the same way. The only Python change is
  the installer entry; tests are template contract tests in
  `tests/test_reverse_spec_template.py`, following `tests/test_onboard_template.py`.
- **Alternatives**: a Python analysis module producing structured drift. Rejected:
  drift detection here is semantic, not syntactic, so a code module would either
  be a thin wrapper around the same judgment or would restrict findings to what a
  parser can see — narrower than the confirmed requirement.
- **Trade-off**: behavior is verifiable only as written discipline, not as runtime
  assertions. Accepted, matching the established repository pattern.
- **Covers**: REQ-001, NFR-002

### Decision 2: Bind slice to workspace with an in-artifact `Slice:` field

- **Context**: REQ-002 must find the baseline for a slice, while REQ-014 gives
  each generate run its own timestamp-named workspace, so the directory name
  cannot carry the mapping.
- **Decision**: Record the slice path in a `Slice:` header inside the generated
  artifacts; lookup scans workspaces for a matching value.
- **Alternatives**: (a) a central index file mapping slices to workspaces —
  rejected because a shared index is a merge-conflict magnet, the same reasoning
  that made the profile store one-file-per-record (recorded as profile decision
  `D-2026-0812-14054p-2`); (b) encoding the path in the directory name — rejected
  because slice paths contain separators and would not survive the repository's
  kebab-case feature-name contract for spec directories.
- **Trade-off**: lookup reads candidate workspaces rather than consulting one
  index. Acceptable: spec directories are few and the read is cheap.
- **Covers**: REQ-002, REQ-004

### Decision 3: Evaluate the bare run before any baseline lookup

- **Context**: DEC-011 makes the bare run unconditionally a survey, while DEC-005
  makes mode depend on baseline presence. Round 1 of the spec review found these
  could collide once an overview design is confirmed.
- **Decision**: Order the resolver so absence of `[path]` short-circuits to
  overview mode before any baseline lookup runs.
- **Alternatives**: special-casing the overview workspace during lookup — rejected
  as the *sole* mechanism, because an easily-forgotten exception is weaker than
  never performing the lookup at all.
- **Amended during implementation**: both mechanisms are needed and both are
  implemented. The short-circuit covers the bare run; the lookup skip additionally
  covers an explicit `.` path, which is an existing directory and therefore does
  not short-circuit. Without the skip, `reverse-spec .` would match a confirmed
  overview workspace and reconcile against a design-only baseline — a state
  neither this design nor `spec.md` defines.
- **Covers**: REQ-002, REQ-015

### Decision 4: Reference `onboard` as provenance and pin the runtime contract

- **Context**: DEC-007 requires reusing the discipline, while REQ-017 makes every
  repository file evidence-only. Dynamically reading a repository-local sibling
  prompt would let mutable repository content become instructions and would
  contradict that trust boundary.
- **Decision**: Name `/codexspec:onboard` only as design provenance and pin the
  complete applicable runtime behavior in C9. Never open, load, or follow a
  repository-local sibling command or skill. The pinned contract keeps three
  reverse-spec-specific differences: no profile writes, `[path]` is the slice
  boundary, and descendant symlinks are followed only while contained.
- **Trade-off**: maintainers must deliberately synchronize any future change to
  the shared scan invariants instead of inheriting arbitrary sibling text at run
  time. Accepted: authority remains closed while the confirmed behavior stays
  explicit and testable.
- **Covers**: REQ-016, REQ-017

### Decision 5: Bound semantic-mismatch judgment and declare what it declines

- **Context**: `semantic-mismatch` is the hardest of the three kinds and the one
  carrying the feature's core value. Over-reaching produces false drift that
  destroys trust in the report; under-reaching silently misses real deviation.
  REQ-013 already provides `needs-your-judgment` as the honest escape.
- **Decision**: The template requires each `semantic-mismatch` item to quote both
  sides as `evidence` (the code observation and the baseline text). An item that
  cannot be evidenced on both sides is not reported as a mismatch. Where a
  disagreement is visible but its correct resolution is not derivable from
  confirmed intent, the item is still reported with direction
  `needs-your-judgment`. Detection is never suppressed for lack of a direction.
- **Alternatives**: report low-confidence mismatches without both-side evidence —
  rejected, it converts the report into noise; or omit items lacking a derivable
  direction — rejected, it would hide real drift and defeat the confirmed goal.
- **Trade-off**: recall is bounded by what can be evidenced on both sides.
  Accepted as a refinement of REQ-013's existing anti-guessing rule; it changes no
  confirmed behavior. Requiring both-side evidence narrows nothing: REQ-010
  already makes `evidence` a mandatory field on every drift item.
- **Covers**: REQ-009, REQ-010, REQ-013

### Decision 6: The report is an artifact, not a gate

- **Context**: `reconcile.md` structurally resembles the `review-*` reports, which
  do act as gates with a status and score.
- **Decision**: Reuse the familiar report shape, but state in the template that
  `Status` and severity are prioritization aids only, that no command consumes
  them, and that the command emits no pass/fail verdict. Combined with C1 carrying
  no `Auto-Next Chain Advance` and no `Automatic Distillation` section, the
  command is fully decoupled from the pipeline.
- **Covers**: REQ-011, REQ-018

### Decision 7: A workspace declares itself at creation, and a resume completes rather than rewrites

- **Context**: Three separate review findings — a resume silently overwriting a
  hand-corrected draft, an interrupted overview run losing its `slices.md` marker,
  and a workspace being invisible to lookup between directory creation and the
  `Slice:` header — turned out to be one defect. The command inferred a workspace's
  identity and state from **content artifacts that are themselves written
  incrementally during the run**. Any artifact used as a state marker is also a work
  product being streamed, so mid-run the marker set is partial and a partial state is
  indistinguishable from a different state. Provenance is likewise unknowable: the
  command cannot tell its own interrupted output from the maintainer's corrections.
  Repairing the three symptoms separately produced two consecutive rounds in which
  the previous round's repair introduced the next round's worst finding.
- **Decision**: Two rules, applied together.
  1. **Identity precedes publication.** Creating a workspace is one indivisible
     publication act: prepare a temporary non-workspace directory as a same-device
     sibling of the final path, write and validate its identifying artifact
     (`spec.md` with the `Slice:` header in generate mode, `slices.md` in overview
     mode), then publish with one host-native atomic no-replace directory rename.
     A runtime that cannot prove the primitive stops; it never emulates the
     guarantee. No interruption window exists in which an official workspace is
     unfindable or readable as the other mode.
  2. **Resume completes; it never rewrites or changes existing content
     automatically.** Content present when a run begins is treated as the
     maintainer's. Missing artifacts may be created; appending to a present artifact
     requires prior explicit confirmation of the disclosed addition. A discrepancy
     is reported, not corrected; a complete draft causes no write.
- **Why this is not new product intent**: rule 2 is strictly more conservative than
  the confirmed text and follows from REQ-017 ("MUST NOT automatically modify code
  or any pre-existing artifact") read together with `spec.md`'s confirmed boundary
  row for a re-run ("Continue the existing workspace"). It also removes the apparent
  tension between User Story 3 (refuse and report) and NFR-004 (resumability): when
  nothing is missing, completion-only *is* report-only.
- **Alternatives**: (a) prompt for consent before each overwrite — rejected because
  overwriting remains forbidden; the chosen one-time gate permits only append of
  disclosed missing content and is required by CON-004; (b) a dedicated workspace state file — rejected
  as a third mechanism where the artifacts already carry the two markers needed;
  (c) keep the closed exception list in C10 and add resume as a third exception —
  rejected, it is the shape that produced the contradiction.
- **Trade-off**: a resumed run cannot improve a section it already wrote, even when
  a wider scan would now write it better. Accepted: the alternative is destroying
  maintainer corrections, and the discrepancy is still surfaced in the report.
- **Covers**: REQ-002, REQ-004, REQ-008, REQ-015, REQ-016, REQ-017, NFR-004

### Decision 8: Normalize the slice path, and let only an exact match choose a mode

- **Context**: C2 step 4 said only that the lookup finds a workspace whose `Slice:`
  value "matches" the path. The write side was pinned to a repo-relative path; the
  read side defined neither normalization nor the match predicate. REQ-002 speaks of
  a workspace **covering** the slice and of several workspaces that **could cover**
  it, so the ambiguity was load-bearing in two directions, both reachable:
  - **Miss** — `src/auth/` (shell tab-completion), `./src/auth`, or an absolute path
    compared against a stored `src/auth` finds nothing, silently creating a *second*
    workspace for a slice that already has one and skipping the drift check that is
    the feature's confirmed purpose.
  - **False match** — with a confirmed workspace at `src/auth`, running
    `reverse-spec src/auth/tokens` yields exactly one covering match, so the
    multiple-match branch never fires. Reconcile would then write into that wider
    slice's workspace, overwriting a `reconcile.md` that holds the user's recorded
    adjudications, and report everything else under `src/auth` as
    `unimplemented-spec`.
- **Decision**: two parts.
  1. **Normalize on both sides.** Symlinks resolved to the real directory,
     repo-relative, `.`/`..`/absolute resolved, trailing slash dropped — applied
     when the `Slice:` header is written and when it is compared. The rule is that
     **one directory reached by any spelling is one slice**; the listed forms are
     examples, not a closed list, since an alias the list omits reopens exactly the
     duplicate-workspace harm this decision closes.
  2. **Only an exact match selects a mode.** A covering (proper-ancestor) match is
     reported and the user chooses: use that wider workspace at its own boundary, or
     create one for the narrower path. A workspace nested *inside* the given slice
     is disclosed as an overlap but does not block.
- **Also settled here**: a path resolving to the **repository root** is the bare run
  and takes the architectural survey. This makes NFR-005's unconditional "no output
  aggregates the whole repository into a single detailed specification" hold for
  every input, and makes `reverse-spec .` and `reverse-spec` the same run — which is
  what a user would expect of them.
- **Provenance**: both parts were adjudicated by the user during implementation.
  Confirmed intent genuinely supported two readings in each case — REQ-002's
  "covering" wording against the harm covering-match reconciliation causes, and
  REQ-014's "a directory path" (the root is one) against NFR-005's unconditional
  sentence — so neither was an implementation choice to make unilaterally. Recorded
  in `requirements.md` as a Confirmation Log entry.
- **Alternatives**: (a) reconcile against the covering workspace — rejected by the
  user; it produces spurious `unimplemented-spec` for the rest of the wider slice and
  destroys another slice's recorded adjudications; (b) exact-equality only, nested
  path silently generates its own workspace — rejected; it makes REQ-002's "covering"
  and "could cover" wording and the multiple-match branch near-dead letters, and lets
  overlapping workspaces proliferate with no defined authority between them.
- **Trade-off**: one extra interaction in the covering case. Accepted: it is the same
  never-guess discipline REQ-002 already mandates for multiple matches and REQ-013
  mandates for drift direction.
- **Covers**: REQ-002, REQ-004, REQ-014, REQ-015, NFR-005

### Decision 9: Partial confirmation keeps the workspace unconfirmed

- **Context**: file-level confirmation makes `spec.md: confirmed` plus a present
  `design.md: open` reachable, but the original design assumed artifacts were
  confirmed as a whole.
- **Decision**: reconcile requires a confirmed spec and every present design to be
  confirmed. Any present open, missing-status, or unreadable baseline artifact
  takes the resume-generate branch. An absent spec also takes that branch even if
  a present design is confirmed; a genuinely absent design retains the confirmed
  spec-only fallback.
- **Alternative**: ignore a present open design and reconcile against the spec
  alone. Rejected because it silently excludes an artifact the user has not yet
  approved and makes its presence operationally meaningless.
- **Trade-off**: a user who confirms files one at a time cannot reconcile during
  the transient partial state. Accepted in favor of never comparing code against
  inferred content.
- **Covers**: REQ-007, REQ-008, REQ-022

## Interface Contract

| Surface | Contract |
|---|---|
| `/codexspec:reverse-spec` | No argument → overview mode. |
| `/codexspec:reverse-spec <path>` | Existing path to a directory, module, or package (or a file set within one) → generate or reconcile per C2, even when its name resembles changeset syntax. |
| Unsupported input | A non-existing argument with diff or pull-request syntax is not a slice source; the command reports the path-only contract. |
| Invalid path | Reported; no workspace and no artifacts are created. |
| Path with no analyzable code | Reported as nothing to reverse-derive; no workspace created. |

        │

                        │                            spec.md + design.md + requirements stub

                        │                                     │
                        │                            user confirms (Status → confirmed
                        │                            + Confirmation Log)
                        │                                     ▼
                        ├── spec + every present design confirmed

## Risks & Trade-offs

| Risk | Mitigation in this design | Residual |
|---|---|---|
| Semantic-mismatch detection is shallow or noisy — the feature's core value | Decision 5: both-side evidence required to report a mismatch; `needs-your-judgment` when direction is underivable; detection never suppressed for lack of direction | Recall is bounded by what can be evidenced on both sides; genuinely subtle deviations may go unreported |
| Users never confirm, so reconcile never activates and the anti-drift value never lands | C6: the generate-mode summary states the exact confirmation action; C2 reports the unconfirmed condition explicitly instead of failing silently | Confirmation remains a manual step by confirmed design (DEC-012); this design does not add an enforcement mechanism |
| Baseline lookup misses or double-matches a slice | Decision 2 gives an explicit `Slice:` field; C2 rejects inconsistent values within one workspace and asks the user on multiple matching workspaces rather than guessing | A hand-moved or hand-renamed slice path requires the user to update every present slice artifact consistently |
| Any derived observation persists a repository or baseline secret | C10 redacts only the sensitive value from every artifact and conversation output while retaining location and non-sensitive context; C2 refuses secret-bearing identity paths without echo | Detection is heuristic; unknown secret formats may require user review |
| A workspace filename is a hardlink to an outside file | C3 opens relative to a verified workspace handle with no-follow semantics and verifies single-link count and stable identity on the opened object | Unsupported runtimes stop rather than degrade |
| A workspace artifact is replaced after validation | C3 retains verified directory/artifact handles through access and never reopens by path | Platform primitives differ, increasing executor complexity |
| Random workspace ID collides with an occupied directory | C3 uses exclusive creation and redraws each untried `rr`; it never reuses the collision | The finite namespace can be exhausted, which is reported without writing |
| Windows/POSIX separators diverge, or canonically equivalent Unicode names coexist | C2 persists `/` while preserving exact Unicode code points and never normalizes or case-folds identity; C3 uses ASCII kebab with `slice` fallback only for the human suffix | Case-insensitive filesystems cannot represent every distinct spelling that a case-sensitive filesystem can |
| Execution stops between directory creation and identity write | C3 prepares and validates identity under a same-device non-workspace temporary name, then uses a native atomic no-replace primitive | A leftover temporary directory can require explicit cleanup after it is reported |
| The host lacks a permitted atomic no-replace directory primitive | C3 stops before publication and forbids weaker emulation | Generate/overview cannot create a workspace until the prerequisite is available |
| A path or evidence span contains structure-forming controls | C2 rejects controls in `Slice:` identity; C8 renders controls elsewhere as escaped code-point tokens | Unusual filenames become less readable but remain unambiguous |
| Existing reconcile adjudications would be replaced | C8 discloses the loss and waits for explicit confirmation | The workflow pauses until the user answers or preserves the old report |
| Resume would append to a maintainer-owned artifact automatically | Decision 7 discloses exact missing content and waits for explicit confirmation; refusal preserves the file byte-for-byte | Resume may pause, but absent artifacts can still be created safely |
| Empty-slice refusal races workspace creation order | C3 makes the read-only analyzable-code preflight the sole pre-publication scan | The preflight is shallow by design and does not replace substantive scanning |
| Duplicate status metadata makes mode selection executor-dependent | C2 rejects more than one file-level `Status:` line before interpreting its value | Hand-edited artifacts must remove the ambiguity before the workflow resumes |
| A large repository makes the scan expensive | C9's referenced discipline is high-signal-first, streaming, and resumable | A very large repository still yields a sampled, not exhaustive, view — reported as such |
