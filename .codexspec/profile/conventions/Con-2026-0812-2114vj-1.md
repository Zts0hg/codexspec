### Con-2026-0812-2114vj-1: Editing a distributed command's frontmatter description/argument-hint requires updating the translation catalogs

- claim: When you change the `description` or `argument-hint` frontmatter of a distributed command that already has a translation-catalog entry, you MUST update `templates/translations/en.json` to match the template (or `test_en_translation_catalog_matches_template_frontmatter` fails on drift), and should update the 7 localized JSONs (`de/es/fr/ja/ko/pt-BR/zh-CN`) in lockstep with translated text — all 9 catalogs carry identical top-level keys. A brand-**new** command needs NO catalog entry: the catalog is a subset (the test skips any command absent from `en.json`), matching the existing `debug`/`distill`/`evolve`/`config` precedent, so those install with English frontmatter.
- type: convention
- scope/when: editing frontmatter description/argument-hint of an existing distributed command, or adding a new command, in the codexspec repo
- evidence.facts: full suite failed with `test_en_translation_catalog_matches_template_frontmatter` → "en.json/spec-to-plan description drifted from template: template: Convert a confirmed design into a traceable implementation plan / en.json: Convert a confirmed specification into a traceable technical plan" after spec-to-plan's frontmatter was narrowed. The argument-hint value `[spec.md or feature directory]` is shared by both spec-to-plan and review-spec, so a value-based string replace is unsafe — update by JSON key. The two new commands (spec-to-design, review-design) were deliberately given no catalog entry and the test passed.
- evidence.state: observed at feature 2026-0812-2114vj-spec-to-design, base commit 8e2aea6.
