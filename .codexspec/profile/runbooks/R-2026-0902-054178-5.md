### R-2026-0902-054178-5: Release a new CodexSpec version through stacked PRs and a manual version bump

- claim: The end-to-end steps (and failure recovery) to cut a release after feature PRs have merged, using a manual version bump and `publish.sh`.
- type: runbook
- scope/when: publishing a new version of this repo to PyPI with a GitHub tag and marketplace metadata update
- steps: 1) land each feature as its own squash-merged PR and confirm main CI fully green first (constitution Principle 8: `gh pr checks` / `gh run watch --exit-status`); 2) cut a release branch from `origin/main`; 3) bump the version manually in `pyproject.toml`, `src/codexspec/__init__.py` `__version__`, add a CHANGELOG entry, and run `uv lock` (do not rely on `--auto-bump`; it does not touch `__version__`); 4) run `codexspec init --here --force --ai both` and confirm the derived copies produce no diff; 5) commit `chore(release): bump version to vX.Y.Z` and push `HEAD:main`; 6) watch main CI to green for that exact commit; 7) run `./publish.sh` — it runs the distribution gate, cleans `dist/`, builds, uploads to PyPI, tags `vX.Y.Z`, then updates and commits `marketplace.json`; 8) push the marketplace commit to main with `git push origin HEAD:main` (publish.sh pushes `origin HEAD`, which is the release branch), delete the temporary remote release branch, and verify the PyPI project page returns 200.
- failure-recovery: if the `pip-audit` pre-commit hook aborts on a transient SSL error, follow publish.sh's own recovery note: reset the half-applied bump and rerun with `SKIP=pip-audit`; if the twine upload fails on the network, nothing has been tagged yet (upload precedes tagging in the script) — fix connectivity and rerun `./publish.sh`; never push the release tag manually to "finish" a failed upload; if the marketplace commit lands on the release branch instead of main, `git push origin HEAD:main` fast-forwards it.
- evidence.facts: "publish.sh 不自动 bump __version__；pip-audit 偶发 SSL 失败中止发布" (earlier release); v0.7.15 was released on 2026-09-07 through exactly this flow (publish output: "Publish Complete! Version: 0.7.15"; PyPI page HTTP 200).
- evidence.state: confirmed at release v0.7.15 (bump commit 06e5c74, marketplace commit 50b1376, tag v0.7.15). Still valid.
- provenance: distill @release v0.7.15, 2026-09-07, derivation: inferred, confidence: high
- status: candidate
