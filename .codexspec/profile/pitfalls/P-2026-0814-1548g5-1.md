- claim: Adding a category to `src/codexspec/profile.py::PROFILE_CATEGORIES` is not just a tuple edit — every prose enumeration of the category set/count across templates, `CLAUDE.md`, and their locking tests must be updated in the same change, or the review gate keeps failing one stale site per round.
- type: pitfall
- scope/when: adding (or removing) a `.codexspec/profile/` category in the codexspec repo
- consolidation: candidate; cluster: enumerated-set-lockstep
- root-cause: the category set is the single source of truth in one place (`PROFILE_CATEGORIES`, which drives both the scaffold and the rendered block), but it is *also* re-stated as English prose in many places that the tuple does not mechanically update: `onboard.md` names the count/list at **three** spots (scaffold prerequisite line, the "two of the N" extraction lead-in, and the exclusion bullets), and `CLAUDE.md` architecture prose restates the store at **four** spots (distill feature blurb + three profile-consumption bullets). Contract tests that assert the old phrasing (e.g. `assert "four category directories" in content`) *lock* the stale wording so the full suite stays green while the docs are self-contradictory — the defect is semantic, not a red test.
- workaround: before implementing, run one repo-wide sweep for every enumeration form and fix them all in the same change: `grep -rnE "four categor|of the four|\{constraints,conventions,pitfalls,decisions\}|N category director" templates/ src/ CLAUDE.md AGENTS.md tests/`. Then regenerate derived forms via `codexspec init . --force --ai both` and re-grep `templates/ .claude/ .agents/` to confirm zero stale copies. Update the locking tests to the new count in the same pass.
- lesson: a "single source of truth" constant is only single for *code*; its human-language restatements are a shadow enumeration set with no compiler. When you change such a constant, grep for the value's prose forms across the whole repo up front — do not trust the plan's or the reviewer's enumerated sites, which surface one-at-a-time.
