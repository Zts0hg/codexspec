### P-2026-0901-15339w-1: Sessions resolve `/codexspec:*` commands from the launch directory's install copies, not the current worktree's

- claim: In the bare-repo + sibling-worktrees setup, a session launched from `/Users/xiaoming/code/codexspec` loads `/codexspec:*` commands from that directory's physical `.claude/commands/codexspec/` — regenerating install copies inside a feature worktree does not change what such a session actually executes.
- type: pitfall
- scope/when: verifying command-UX changes in a worktree while the session was launched from the bare repo directory
- root-cause: Claude Code registers project skills/commands from the launch directory's `.claude/commands/`. The bare repo has a physical, untracked `.claude/` left by an old install; each worktree is a separate checkout with its own `.claude/commands/codexspec/`, and nothing shares state between them — so a "fresh" worktree copy is invisible to sessions launched elsewhere, and the bare dir's copy silently stays stale (this one predated the schema-v2 review-code rework).
- workaround: regenerate each checkout's copies that must be current, via the installer: `install_commands_to_subdir(Path("<checkout>/.claude/commands/codexspec"), Path("templates/commands"), force=True, language="zh-CN")` run from a checkout holding the current templates. The installer only writes template-backed files and never deletes, so internal-only commands (`translate-docs`, `check-i18n-semantics`) survive — but merged/removed commands leave zombie copies that need manual deletion (e.g. `review-python-code.md` / `review-react-code.md` after 6b41489 folded them into `review-code`; the docs site still referenced them).
- lesson: install-artifact state is per-checkout, not per-repo. Before concluding a command change "isn't taking effect", confirm which copy the running session resolves (launch dir) — invoke the command and inspect which body/frontmatter actually loaded.
- evidence.facts: invoking `/codexspec:review-code src/` in-session loaded the pre-schema-v2 body ("Argument-error envelopes use schema version `1`", no `## Usage Hints` section) while the worktree's regenerated copy had schema v2 and the new section; `/Users/xiaoming/code/codexspec/.claude/commands/codexspec/review-code.md` was the stale file. After running the installer against it, the session picked up the refreshed body and two previously missing commands (`blueprint`, `auto-dev`) appeared in the skill list. See also [[P-2026-0812-2114vj-1]] (regenerate derived forms during the feature, not at release).
