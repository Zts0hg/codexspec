## P-2026-0813-1606fz-1: Markdown emphasis inside an asserted phrase breaks template-contract substring tests

- claim: When a template-contract test asserts a literal substring of a command template under `templates/commands/*.md`, pick a span that avoids any word the template wraps in markdown emphasis (`**bold**`, `*italic*`, backticks) — the emphasis markers live *inside* the raw phrase, so a naive `assert "Do not block until" in content` fails against a template that wrote `Do **not** block until`. Assert an emphasis-free span (e.g. `"block until the whole scan finishes"`), and prefer that over changing the template just to satisfy the test.
- type: pitfall
- scope/when: writing substring-based contract tests over the `templates/commands/*.md` command templates in the codexspec repo (`test_onboard_template.py`, `test_debug_template.py`, `test_release_notes_template.py`, …)
- evidence.facts: `test_onboard_scan_is_streaming_and_resumable` asserted `"Do not block until" in content` and failed because `onboard.md` wrote "Do **not** block until the whole scan finishes"; re-asserting the emphasis-free span "block until the whole scan finishes" turned it green with the template unchanged. The template behavior was correct; only the test's asserted string was wrong.
- evidence.state: observed at feature 2026-0813-1606fz-onboard, base commit 1a0a49e; verified by outcome (17/17 onboard contract tests green after the assertion fix, full suite 1165 passed). Same substring-contract-test pattern as [[P-2026-0811-1418yq-1]]'s sibling test files.
