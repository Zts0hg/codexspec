### P-2026-1013-1133ii-1: Filesystem identity must precede source classification

- claim: When an admitted file's identity determines behavior, filesystem-equivalent path spellings must retain the same source surface and parent-relative mapping.
- type: pitfall
- scope/when: classifying selected files or directory prefixes in maintainer helpers that run on both case-sensitive and case-insensitive filesystems
- root-cause: POSIX Path equality and lexical prefix comparisons remain case-sensitive on a case-insensitive macOS volume. The same regular README can enter a site mapping, and the same English directory can lose its relative hierarchy. Lowercasing every existing path would instead conflate genuinely distinct files on a case-sensitive filesystem. An ASCII case alias proves neither canonical Unicode normalization nor full Unicode case-fold equivalence; NTFS can alias docs/DOCS while preserving café.md and cafe\u0301.md as distinct names.
- workaround: Inspect all raw path ancestors for links and invalid components before rebasing. Establish checkout containment with the selected root directory identity, preserving genuine prefix aliases while refusing redirected or different checkouts; then validate file kind. Recover actual entry spelling for accepted aliases and compare file/directory identities with samefile or device/inode values when assigning the source surface or parent. Refuse unavailable reserved source forms before unrelated shorthand fallback. Reserve folded aliases only where a real namespace alias establishes case folding, preserving valid shorthand on a case-sensitive namespace. Test physical samefile aliases, missing and directory forms, nested mappings and distinct-file controls; report platform skips explicitly.
- lesson: Lexical admission checks and physical source identity establish different facts. Use each for its own contract rather than treating a spelling comparison as proof of the selected object's identity. Accepted source identity also does not establish prospective output uniqueness: two distinct inputs can project to absent target names that the destination namespace treats as one file. Check the entire projected output set before incremental omission. Derive component comparison keys only from name transformations proved by samefile against admitted components; evaluate canonical normalization separately from case folding. Preserve original resource strings and names that the filesystem distinguishes, including full-casefold expansions such as Straße/STRASSE when they are not aliases.
