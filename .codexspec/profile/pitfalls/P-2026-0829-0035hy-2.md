## P-2026-0829-0035hy-2: Strict result parsers need relationship validation, not only field validation

- claim: A fail-closed structured-result parser must validate the allowed object shape and cross-field relationships in addition to validating each field independently.
- type: pitfall
- scope/when: adding or upgrading a structured result schema consumed as a correctness or workflow gate
- root-cause: required-field, type, enum, count, and reference checks can all pass while the combined result remains impossible, such as a target-limited selector claiming complete-feature coverage, a non-defect verdict carrying admitted defects, or a specialist-owned partition with no matching specialist. Allowing undocumented extension fields also makes the accepted schema broader than its producer contract.
- workaround: derive a schema-to-validator matrix that includes exact allowed keys and relational rules across target identity, selector, coverage, findings, verdict, follow-up, gaps, and reviewer topology. Add one negative test per incompatible state pair or group, not only per malformed individual field.
- lesson: local validity does not imply envelope validity; any strict protocol with multiple entities needs explicit relational validation and contradiction tests.
- evidence.facts: The schema-v2 evaluation parser passed all existing tests while accepting an undeclared top-level field, an unrelated gap for a null fingerprint, an INCONCLUSIVE result with a finding, an unmatched specialist partition owner, and an uncommitted target claiming complete-feature coverage. Adding exact-key and relationship checks made all counterexamples reject while the valid envelopes continued to pass.
