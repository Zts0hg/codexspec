## P-2026-0829-0035hy-2: Strict result parsers need relationship validation, not only field validation

- claim: A fail-closed structured-result parser must validate the allowed object shape and cross-field relationships in addition to validating each field independently.
- type: pitfall
- scope/when: adding or upgrading a structured result schema consumed as a correctness or workflow gate
- root-cause: required-field, type, enum, count, and reference checks can all pass while the combined result remains impossible, such as a target-limited selector claiming complete-feature coverage, a complete feature paired with partial requirements coverage, a non-defect verdict carrying admitted defects, or a partition whose owner reviewer did not run. Conversely, applying feature-completion rules to a code-level success or successful-state relationships to an unresolved error state can reject an honest result. Treating an optional field as nullable and allowing undocumented extensions likewise broadens the accepted schema beyond its producer contract.
- workaround: derive a schema-to-validator matrix that includes exact allowed keys, success and error states, gate scope versus feature-readiness scope, optional-versus-nullable rules, and bidirectional relationships across target identity, selector, coverage, findings, verdict, follow-up, gaps, and reviewer topology. Add negative tests for every incompatible state pair or group and positive tests for every intentional scoped-success, degraded, and error state, not only malformed individual fields.
- lesson: local validity does not imply envelope validity; any strict protocol with multiple entities needs explicit relational validation and contradiction tests.
- evidence.facts: The schema-v2 evaluation parser passed all existing tests while accepting undeclared fields, unrelated or contradictory target/reviewer states, a null optional specialist reason, and complete-feature/partial-requirements combinations; a later strict selector matrix rejected both the required blocked result when target identity could not be resolved and valid code-level PASS results without complete feature coverage. Extending the matrix with explicit scoped-success/error states and optional/null rules made the counterexamples reject while valid code-level, complete-feature, and intentionally degraded envelopes continued to pass.
- evidence.state: observed and outcome-verified across repeated reviews of feature 2026-0829-0035hy-review-code-systematic-coverage; applicable to future structured gate schemas.
